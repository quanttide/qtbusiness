# qtbusiness 产品需求文档（服务黄页）

量潮商务（qtbusiness）服务黄页产品需求文档。设计输入：商务拓展日志（`data/journal/`）与业务档案（`data/profile/`）。

## 业务背景

### 工作角色

- **潜在客户（业务方）**：有定制需求（数据服务、咨询、定制开发），需要找到可信的供应方
- **商务拓展人员**：负责把服务卖出去、把询盘变成成交

### 问题

定制服务没有产品形态，难以被看见、被评估、被信任：

1. **看不见**：服务不挂在货架上，客户不知道"你们能做什么"——产品黄页能解决产品的展示，定制服务没有对应载体；
2. **信任成本高**：市场缺乏诚信渠道——渠道需要信息与信任，而整个市场信息不透明、互相不信任（2026-08-12 日志）；大厂用标准方案去凑，客户难以判断谁真正懂自己；
3. **相关性缺失**：宣传册不回答"这跟我有什么关系"——客户关心的是"你懂不懂我这一类客户、过往做过什么合作"（2026-07-12 日志）；
4. **被动等待**：商务拓展的本质是从被动到主动——主动设计商业模式、主动展示能力，而不是完全跟着客户的需求走（2026-08-17 日志）。

### 假设

如果存在一个服务黄页，让客户按自己的场景看到服务、案例与定价模式，并直接发起询盘，商务拓展就能从"等人来找"变成"主动被看见"，用公开透明的展示代替不可靠的渠道。

## 产品定位

服务黄页——展示没有产品形态的定制服务与解决方案（数据服务、咨询、定制开发），与 qtproduct 构成产品与服务**双黄页**。

- **商务拓展的对外窗口**：把服务能力、案例与商业模式主动展示给市场；
- **商业模型的宣传载体**：商业模型可以公开——挣钱靠实际交付，模型本身需要宣传（2026-08-17 日志）；黄页公开"怎么收费"（项目制、处理费、存储费、咨询按次），本身就是信任建设；
- **成交流程的入口**：黄页负责"被看见与被询盘"，商务云负责"报价与合同"，构成商务五步流程（澄清需求 → 谈判生成合同订单 → 实施 → 交付验收 → 复盘）的前端（2026-08-11 日志）。

## 产品边界

| 维度 | qtproduct | qtbusiness | 商务云 | 销售云 |
|------|-----------|------------|--------|--------|
| **形态** | 产品黄页（产品形态服务） | 服务黄页（定制服务与解决方案） | 后端成交工具 | 潜客管理工具 |
| **核心动作** | 展示产品 | 展示服务与案例 | 报价、签合同 | 归集、跟进潜客 |
| **阶段** | 获客展示 | 获客展示 | 成交 | 获客后段 |

协作关系：

```
潜在客户 → 服务黄页（看见服务/案例/定价） → 询盘 → 商务云（报价→合同） → 实施交付 → 复盘沉淀
```

黄页还承担**导流枢纽**职责：询盘与流量可向课堂、产品、数据云等变现出口导流（招聘日志的导流思路：以入口承接流量，再往其他业务变现）。

## 核心能力

### 1. 服务与解决方案展示

- 服务目录：数据服务、咨询、定制开发等条目，每个条目包含服务内容、适用场景、交付物；
- 解决方案页：按客户场景（行业、问题类型）组织的解决方案，直接回答"这跟我有什么关系"。

### 2. 案例库

- 按客户行业/场景组织过往合作案例，展示"我们懂这一类客户"（宣传册逻辑：客户的过往合作是客户最感兴趣的信息）；
- 案例与所属服务条目关联，形成"服务 → 案例"的信任证据链。

### 3. 定价模式公开

- 服务条目上展示收费方式与价格档位：项目制报价、按量处理费（几毛几分一次）、存储年费、咨询按次（源自 `data/profile/` 中 qtdata/qtcloud 的以数据为中心定价模型）；
- 公开定价即公开商业模型，降低客户评估成本与信任成本。

### 4. 询盘入口

- 服务/案例页一键发起询盘，携带客户场景信息；
- 询盘自动进入商务云流程（澄清需求与初步报价），黄页与商务云在数据上打通。

### 5. 导流机制

- 黄页条目可挂接导流目标（课堂、产品黄页、数据服务等），把展示流量导入变现出口；
- 低门槛服务条目（免费/小额服务）作为增长漏斗入口，吸引规模后再向上导流。

## 用户故事

**US1**：作为潜在客户，我希望按我的场景找到相关服务，以便判断"你们能帮我做什么"。

- 接受标准：能按行业/问题类型浏览解决方案；能看到服务适用场景与交付物

**US2**：作为潜在客户，我希望看到与我类似的过往案例，以便判断"你们懂不懂我这一类客户"。

- 接受标准：案例可按行业/场景筛选；案例展示问题、做法与结果

**US3**：作为潜在客户，我希望在询盘前了解收费方式，以便评估预算。

- 接受标准：服务条目展示定价模式（项目制/按量/年费）；能通过询盘获得正式报价

**US4**：作为潜在客户，我希望一键发起询盘并知道后续流程，以便推进合作。

- 接受标准：询盘表单携带服务与场景信息；提交后进入商务云流程并可见状态

**US5**：作为商务拓展人员，我希望发布和维护服务条目与案例，以便黄页反映真实能力。

- 接受标准：能创建/编辑服务条目与案例；能查看条目的浏览与询盘数据

**US6**：作为商务拓展人员，我希望管理询盘并跟踪其成交结果，以便评估黄页效果。

- 接受标准：询盘列表与状态流转；询盘到成交的转化可统计

## 核心指标

| 指标 | 说明 |
|------|------|
| 询盘转化率 | 浏览量 → 询盘的比例，衡量内容相关性 |
| 服务覆盖度 | 已发布服务条目对目标场景的覆盖率 |
| 案例 → 询盘率 | 案例详情的询盘转化，衡量信任建设效果 |
| 黄页 → 成交率 | 从黄页询盘到商务云签约的转化 |

## 演进方向

1. **供应链池展示**：服务条目与执行方/合作方挂钩，支撑三方平台（客户/执行方/平台方）与供给侧整合（源自 qtdata 档案）；
2. **与商务云深度打通**：询盘自动生成需求澄清会话，报价单直接引用黄页条目；
3. **商业模型判例沉淀**：服务条目随商务谈判结果演化，成为商业模型的高层次抽象单元（2026-08-17 日志：商业模型是各种商务谈判结果的高层次抽象）。
